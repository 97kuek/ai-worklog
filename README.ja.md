# Taskfolio

[English](README.md) · 日本語

Taskfolio は、Claude Code と Codex の作業を振り返るためのセルフホスト型の作業記録ツールです。どのプロジェクトで、いつ、どれくらい作業したかを確認できます。ボードから依頼を送ると、Mac に登録したフォルダーでエージェントが実行します。

**現在はプレアルファ版です。** 1 つのデプロイを 1 人で使います。Web アプリは Cloudflare Workers、D1、Cloudflare Access で動きます。作業記録を収集するコレクターと、依頼を実行する任意のランナーは、それぞれ Mac で動きます。

## 手元の記録を試しに読む

このリポジトリを取得し、ルートディレクトリで次のコマンドを実行すると、過去 7 日間の記録を表で確認できます。安定版の新しい Rust が必要です。Cloudflare の設定は後から始められます。

```sh
cargo run --locked --manifest-path cli/Cargo.toml -- scan --since-days 7 --format table
```

1 つのセッションが 1 件のタスクになります。初期設定では、記録の間隔が 30 分以上空くと作業を区切ります。作業時間は各区間の長さの合計です。Web アプリでタスクを選ぶと、ブランチ、モデル、トークン数、個々の作業区間を確認できます。

## 作業記録を使い始める

1. 自分の Cloudflare アカウントに Worker とデータベースを用意し、公開先のホスト名を Access で保護します。
2. 各 Mac に CLI をインストールし、Mac ごとに発行した Access サービストークンでログインします。
3. コレクターを実行してブラウザーで **Work log** を開きます。コレクターは既存のセッションログを読み、更新分を Worker に送ります。

コマンド、設定値、動作確認の手順は[セットアップガイド](SETUP.ja.md)にまとめています。

## Mac でボードの依頼を実行する

任意でランナーを導入すると、ボードから依頼を実行できます。作業フォルダーを登録し、ランナーをインストールしたら、歯車アイコンから **Settings** を開いて Mac からの接続を確認します。**Board** で依頼を作り、プロジェクトとエンジンを選んで **Backlog** から **Queued** に移すと、条件に合う Mac が依頼を受け取り、実行結果を報告します。[ランナーの設定手順](SETUP.ja.md#ボードの依頼を実行する)

## 画面の使い方

| 画面 | できること |
| --- | --- |
| Work log | 週ごとの作業を見返し、曜日や状態で絞り込めます。変更したタスク名は次の収集後も保持されます。 |
| Calendar | 同時に進んだ作業を横に並べて表示します。作業区間は現地時刻の午前 0 時で分かれます。小さな画面では 1 日ずつ選べます。 |
| Board | 依頼の計画、実行中・待機中のタスクの確認、待機中のセッションの完了操作ができます。Completed 列には直近 7 日間の完了分が表示されます。 |
| Activity | 時間帯や日ごとにプロジェクトの作業時間を比較できます。同時に作業した時間は 1 回だけ数え、その間に動いていたプロジェクトで均等に分けます。時間帯を選ぶとプロジェクトとモデルの内訳が表示されます。 |
| Skills | 各ツールが報告したスキルの名前と説明を確認できます。コレクターは通常、ホームディレクトリで各ツールに問い合わせます。特定のプロジェクトで調べるには `skills_cwd` を設定します。 |
| Office | 3D オフィスで作業中の人物か一覧のタスク名を選ぶと、タスクの詳細を開けます。表示中は 15 秒ごとに更新されます。 |
| Settings | Mac ごとの最終接続時刻、登録フォルダー、エンジンを確認できます。フォルダー横のスイッチで新規依頼の実行を一時停止・再開できます。 |

## Mac から送るデータ

- **作業記録の収集。** Worker には、Mac の表示名、セッション ID、タスク名、プロジェクト、作業ディレクトリ（絶対パスを含む場合があります）、ブランチ、ツール、モデル、推論レベル、状態、時刻、メッセージ数、トークン使用量を送ります。スキル一覧にはツール名、スキル名、説明が含まれます。元のセッションログは Mac に残ります。[送信データの例](contract/ingest.example.json)
- **タスク名の生成。** Codex に保存済みのスレッド名があればそれを使います。名前がなく生成条件を満たしたセッションでは、初期のユーザーメッセージの抜粋を Claude Code 経由で設定済みモデル（初期設定は Haiku）に送ります。自動生成を使わない場合は、最初の収集前に `config.json` の `naming.enabled` を `false` にします。
- **ボードからの依頼。** ボードに入力した依頼文は D1 に保存されます。ランナーは引き受けた依頼文を Mac 上で指定のプロバイダーに渡します。ランナーが Worker に報告するのは、プロジェクトの登録名、利用可能なエンジン、実行状況などです。登録名とフォルダーのパスの対応表は Mac の `runner.json` に保存します。

## Usage

**Usage** では、登録したアカウントごとにトークン数、セッションの推定費用、利用枠の残量とリセット時刻を確認できます。Claude Code は5時間枠と7日間枠に対応しています。Skills はアカウントで絞り込めます。Activity はモデルの利用量をエンジン単位で集計します。[Claude Code アカウントの登録手順](CLAUDE-USAGE.md)
